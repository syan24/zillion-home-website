# Client Requirements - English Baseline

Status: Draft v0.1

This document preserves the client's original scope and intent in English. It does not add new requirements except minor wording clarification.

## Overall delivery approach

**[CLIENT]** Development is split into phases.

- **Phase 1:** launch the company website, project case library, enquiry Quiz and SWMS management as quickly as practical.
- **Phase 2:** progressively add the customer portal and project management functions.

---

# Phase 1 - Website Launch and Core Functions

## 1. Company Website

### Company information
**[CLIENT]** Present company introduction, service scope, qualifications and contact information.

### CMS maintenance
**[CLIENT]** Administrators must be able to update website text, images and project cases without developer assistance.

### Responsive design
**[CLIENT]** The website must work appropriately on desktop, tablet and mobile.

---

## 2. Project Case Library

**[CLIENT]** Project display is a key part of the website. Staff must be able to quickly find suitable project photos and provide them to customers as design and construction references.

### Project category
**[CLIENT]** Projects are initially divided into:
- Residential
- Commercial

### Filter by project
**[CLIENT]** Users can find photos by a specific project name or address.

**[CLIENT]** Administrators can control whether project addresses are publicly visible.

### Filter by style
**[CLIENT]** Example styles include:
- Modern
- Contemporary
- Classic
- Minimalist

**[CLIENT]** Administrators can add additional style tags.

### Filter by space
**[CLIENT]** Example spaces include:
- Kitchen
- Bathroom
- Living
- Bedroom
- Facade
- Office
- Restaurant

### Combined filtering
**[CLIENT]** Users can combine filters such as project type, project, style and space to narrow the image set.

### Case management
**[CLIENT]** Administrators can:
- create projects;
- upload multiple photos;
- add descriptions and tags;
- edit project cases;
- change ordering;
- unpublish/remove cases from public display.

### Quick use
**[CLIENT]** Project photos can be:
- viewed at large size;
- downloaded;
- shared using a copied link.

---

## 3. Customer Enquiry Quiz

**[CLIENT]** The enquiry experience should be a short, multi-step Quiz so that too many questions are not displayed at once.

### Customer details
**[CLIENT]** Capture:
- name;
- phone;
- email.

### Project details
**[CLIENT]** Capture:
- project address;
- Residential / Commercial;
- project type;
- project scope.

### Specific requirements
**[CLIENT]** Capture the spaces, work scope, preferred style and/or other requirements.

### Budget and timing
**[CLIENT]** Capture:
- budget range;
- expected start time.

### Attachments
**[CLIENT]** Allow customers to upload existing-condition photos, floor plans or other reference files.

### Submission record
**[CLIENT]** After submission:
- the company receives the information;
- a complete enquiry record is retained in the administration system.

---

## 4. SWMS Management

**[CLIENT]** The SWMS function is for installers/site workers to read, confirm and sign SWMS documents, with records retained against the relevant project.

### Company templates
**[CLIENT]** The company can create reusable SWMS templates and administrators can update the content.

### Project SWMS
**[CLIENT]** Administrators can create a SWMS for a specific project and associate it with the project name and address.

### QR code / link
**[CLIENT]** Each project SWMS can generate an individual QR code and link for distribution to workers or printing/display at the site.

### Mobile completion
**[CLIENT]** After scanning the QR code, a worker can use a mobile device to:
- read the SWMS;
- enter personal information;
- confirm/acknowledge it;
- sign it.

### Signature record
**[CLIENT]** Store:
- signer's name;
- date;
- time;
- signature;
- relevant project;
- relevant SWMS version.

### Archive / export
**[CLIENT]** Administrators can view, search, download and export signed records by project.

### Worker access
**[CLIENT]** Workers do not need access to the company administration system. They can only open the specified SWMS page and complete the signing process.

---

# Phase 2 - Customer Portal and Project Management

## 5. Project Records and Document Confirmation

**[CLIENT]** The company can create an individual record for each project associated with:
- customer;
- project address;
- responsible person;
- project status.

**[CLIENT]** Project records can include:
- quotations;
- contracts;
- drawings;
- material lists;
- selections/specification material;
- reports;
- other project attachments.

**[CLIENT]** Documents are organised by type and date and customers can log in to view/download the latest content.

**[CLIENT]** The company can request customer confirmation/signature for selected quotations, drawings, material lists and other documents.

**[CLIENT]** New document versions can be uploaded while retaining historical versions, timestamps and operation records.

**[CLIENT]** Confirmation records retain the customer's result, name, date, time, signature and document version.

**[CLIENT]** Email notifications are sent for new/updated files, confirmation requests and completed signatures.

---

## 6. Customer Accounts and Project Communication

**[CLIENT]** Customers can have accounts linked to their own projects and addresses and can only view their own data.

**[CLIENT]** The company can upload progress photos and customers can browse them by date or project stage.

**[CLIENT]** Customers can leave messages within a project and retain the conversation history.

**[CLIENT]** Email notifications are sent when progress, photos, messages, files or other project records are added.

---

## 7. Variation Confirmation and Record Keeping

**[CLIENT]** The company can create a Variation within a project, including:
- description/content;
- amount;
- attachments;
- notes.

**[CLIENT]** Customers can view the Variation and either confirm it or raise a question.

**[CLIENT]** Retain:
- Variation version;
- customer confirmation result;
- name;
- date;
- time;
- message history.

**[CLIENT]** Email notifications are sent when a Variation is created, modified or confirmed.

---

## 8. Staff Accounts and Mobile Upload

**[CLIENT]** Staff accounts can be self-created or created by an administrator.

**[CLIENT]** Administrators control which projects and content each staff member may view, upload or edit.

**[CLIENT]** Staff can quickly select a project on mobile and take/upload multiple photos.

**[CLIENT]** Photos can include:
- date;
- project stage;
- short description.

**[CLIENT]** Photos can either be published directly to customers or held for administrator review before publication.

---

## Phase 2 Detail Level

**[CLIENT]** The client explicitly notes that Phase 1 should prioritise getting the website operational, and that detailed Phase 2 workflows can be confirmed after Phase 1 is complete.
